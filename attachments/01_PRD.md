# Product Requirements Document (PRD)
## AI Fitness Tracker App (Android APK)

**Version:** 1.0
**Status:** Draft for build planning
**Owner:** Solo developer, VS Code only, no Android Studio, free-tier tools only

---

## 1. Product Vision

An all-in-one Android fitness app that tracks exercise, weight, meals, and body measurements, connects to Bluetooth smart scales, visualizes progress on a muscle map, and has AI ("Ask AI", powered by Groq) embedded into nearly every input field and a dedicated AI chat that can create/edit data on the user's behalf.

## 2. Target Users

- Individuals doing home/gym workouts who want one app instead of five.
- Users who own a Bluetooth (BLE) smart scale and want auto-synced weight data.
- Users who want AI to do the tedious parts (writing diet plans, logging meals from a sentence, building timetables) instead of manual form-filling.

## 3. Goals / Success Criteria

| Goal | Metric |
|---|---|
| Reduce logging friction | Meal/exercise log takes <15 sec via AI quick-add |
| Reliable BLE sync | Scale weight auto-appears in Weight Tracker within 5s of stepping off scale |
| Useful body measurement | Camera measurement within ~±3–5% of tape-measure ground truth (realistic target — see §7.8 caveats) |
| Retention | Daily streak/challenge system drives 3+ opens/day |
| Buildable by one dev | Full app buildable to a signed `.apk` using only VS Code + free-tier cloud services |

## 4. Non-Goals (v1 Out of Scope)

- iOS app (Android-only for v1; architecture stays cross-platform for later).
- Social feed / friends leaderboard (single-user local-first, optional cloud sync only).
- Medical-grade body composition (this is a fitness estimate tool, not a diagnostic device — must be disclosed to users).
- Payment/e-commerce checkout flow for "buy stuff" notifications — v1 only *reminds/suggests*, does not process purchases (see §7.1).

## 5. Personas

1. **Priya, 27, home workout enthusiast** – wants a diet plan generated by AI and a streak to stay motivated.
2. **Dev, 34, gym-goer with a BLE scale** – wants his scale weight to log itself and see a trend graph.
3. **Alex, 22, tracking a cut** – wants monthly body measurement snapshots without manually measuring 8 body parts with a tape.

## 6. Feature List (Mapped to Your Requirements)

Each feature below has: description, user story, core screens, and MVP-vs-later split.

### 6.1 To-Do / "Buy Stuff" Notifications
- **What:** A to-do/reminder list (e.g., "buy protein powder," "buy new dumbbells") with local push notifications.
- **User story:** As a user, I want to add a reminder and get notified at a chosen time so I don't forget gym-related purchases/tasks.
- **MVP:** Manual to-do list + local scheduled notification (`expo-notifications`).
- **Later:** AI auto-suggests restock items (e.g., "you log whey protein daily, running low? add to list").

### 6.2 Exercise Tracking
- **What:** Log workouts: exercise name, sets, reps, weight, rest timer, duration.
- **User story:** As a user, I want to log a workout in under a minute and see history per exercise (progressive overload chart).
- **MVP:** Preset exercise library + custom exercise + set/rep/weight logger + per-exercise history chart.
- **Later:** AI auto-fills a plan ("generate today's push day").

### 6.3 Bluetooth Watch / Weighing Scale Connection
- **What:** Pair to BLE smart scale (and optionally BLE watch/band) to pull weight (and body-fat % if the scale broadcasts it via standard BLE Body Composition/Weight Scale profiles).
- **User story:** As a user, I step on my scale and the reading appears in the app automatically.
- **MVP:** BLE scan/pair screen, read standard **Bluetooth SIG Weight Scale Service (0x181D)** and **Body Composition Service (0x181B)** if supported by the scale; manual entry fallback for non-standard scales.
- **Later:** Wearable step-count/heart-rate sync (requires each vendor's SDK — flagged as high-risk/variable, see Risks).
- **Hard constraint:** Real BLE scale integration is *not possible in Expo Go* — requires EAS Dev Client build (covered in Tech Stack doc).

### 6.4 Weight Tracker
- **What:** Log weight (manual or BLE), see trend line, moving average, goal-weight progress.
- **MVP:** Log entry, line chart, goal line, weekly change %.

### 6.5 Overall Tracker (Dashboard)
- **What:** A home dashboard aggregating: today's calories vs goal, workout streak, weight trend, upcoming timetable items, AI daily summary.
- **MVP:** Single dashboard screen pulling from all other modules (read-only aggregation).

### 6.6 Daily Record Creator
- **What:** End-of-day (or auto-generated) summary: workouts done, meals logged, weight, mood/notes, AI-written recap ("Ask AI to summarize my day").
- **MVP:** Manual daily note + auto-pulled stats; AI recap is a button, not automatic (cost control on API calls).

### 6.7 Challenge Starter (Streaks)
- **What:** User starts a challenge (e.g., "30-day no sugar," "workout streak"), app tracks daily check-ins and streak count with visual streak calendar.
- **MVP:** Create challenge (name, duration, daily task), daily check-in, streak counter, calendar heatmap.
- **Later:** AI-suggested challenges based on user's logged data.

### 6.8 Camera Body Measurement Tracker
- **What:** User enters height once (reference), opens camera, app detects when the user is fully in frame in a standing pose, and estimates measurements (shoulders, chest, waist, hips, arm, thigh, etc.) using pose landmark ratios scaled against the known height.
- **User story:** As a user, I hold my phone up, the app tells me "step back" / "hold still," then reports my measurements without a tape measure.
- **MVP scope (realistic):**
  - On-device pose detection (landmarks: shoulders, hips, elbows, wrists, knees, ankles, ears/nose).
  - "Good frame" detection: full body visible, roughly frontal, person centered, minimal motion for ~1s → auto-capture.
  - Pixel-distance-between-landmarks → real-world cm using `known_height_cm / pixel_height_of_landmarks` as the scale factor.
  - Output: estimated shoulder width, arm length, leg length, torso length, rough limb "thickness" (width in frontal 2D — **true circumference, e.g. waist/chest in cm-round-the-body, is not physically derivable from one 2D frontal photo**; see Risk section for the honest fix — front+side photo pair, or a regression model).
  - Clear in-app disclaimer: estimates are approximate, for progress-tracking trend purposes, not medical/tailoring accuracy.
- **Later (v2):** Front + side photo pair for real girth estimation via trained regression model; multi-angle capture.

### 6.9 Meal Tracker
- **What:** Log meals/foods with calories & macros; "Ask AI" to log via free text ("2 eggs and toast") which AI parses into structured food + macros.
- **MVP:** Manual entry + food search (local static database, e.g. bundled USDA subset) + AI free-text parsing via Groq.

### 6.10 Timetable Tracker
- **What:** Daily/weekly schedule (workout times, meal times, sleep) with reminders.
- **MVP:** Simple weekly grid, add/edit blocks, notification per block.

### 6.11 Diet Creator
- **What:** AI (Groq) generates a diet plan from user goals (bulk/cut/maintain), preferences, allergies, calorie target.
- **MVP:** Form (goal, calories, diet type, restrictions) → Groq generates a structured multi-day plan → save/edit/regenerate.

### 6.12 "Ask AI" on Every Field + Global AI Chat
- **What:** Every editable field (meal entry, workout plan, diet, timetable, notes) has an inline "✨ Ask AI" affordance that lets the user type/speak a request and AI fills or edits that field. Plus a global chat where AI can create/edit *any* data in the app (add a workout, log a meal, build a week's timetable, start a challenge) via structured function-calling.
- **MVP:** Implement as a shared `AIAssistButton` component wired to Groq with **function/tool calling** so AI returns structured JSON the app applies to state (not just text) — this is the technical core of "AI can create everything for the user."
- **Design pattern:** Every module exposes a small set of "actions" (e.g., `addMeal(name, cals, protein, carbs, fat)`, `addWorkout(...)`, `createChallenge(...)`). The AI chat and every "Ask AI" button call into the *same* action layer, so nothing is duplicated.

### 6.13 Notifications on Everything
- **What:** Configurable local notifications for: to-dos, timetable blocks, meal reminders, workout reminders, streak-at-risk warnings, weigh-in reminders.
- **MVP:** Central `NotificationSettings` screen; every module registers its own notification type through one shared scheduler service.

### 6.14 Complete Body Muscle Map
- **What:** Interactive SVG front/back human body, muscle groups tappable/highlightable — e.g., color muscles worked this week (from exercise tracker data), or tap a muscle to see exercises targeting it.
- **MVP:** Static SVG muscle map (front + back), color-coded by "volume trained in last 7 days" pulled from exercise logs; tap a muscle → filter exercise library by that muscle.

### 6.15 Advanced UI
- **What:** Polished, modern design system — dark/light themes, smooth transitions, charts, consistent component library.
- **MVP:** Design tokens (colors/spacing/typography) + component library (buttons, cards, inputs, charts) built once, reused everywhere. Covered in a separate UI/Design doc.

## 7. Key Risks & Honest Caveats (read before building)

1. **No Android Studio still means installing the Android SDK command-line tools** for local builds — OR skip that entirely and use **EAS Build** (cloud), which needs zero local Android SDK. Strongly recommended path — see Dev Setup doc.
2. **BLE scale integration only works with scales that expose the standard GATT Weight Scale/Body Composition services.** Many consumer scales (e.g., some Xiaomi/Withings models) use proprietary BLE protocols requiring reverse-engineered or vendor SDKs — may not work out of the box. Manual entry must always be the fallback.
3. **Circumference measurements (waist, chest, hip *girth*) cannot be accurately derived from a single 2D frontal photo** — a 2D image only gives you widths, not the roundness of the body. Being upfront with users about this (estimate/trend tool, not tailor-grade) is both an honesty and liability issue. v2 fix: front+side photo pair or ML regression model trained on real data.
4. **Groq API costs/rate limits:** every "Ask AI" click is an API call. Needs client-side debouncing, caching of repeated prompts, and a visible "AI calls remaining" or similar cost-control UX.
5. **"Buy stuff" notifications performing real purchases** would require payment/e-commerce integration (Stripe, Amazon affiliate links, etc.) — explicitly out of scope for v1; keep it to reminders only.
6. **Camera body measurement accuracy depends heavily on camera angle, lens distortion, clothing.** Needs strong UX guidance (silhouette overlay, "stand at 2m, wear fitted clothing") to get usable results.
